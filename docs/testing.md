# Проверки frontend

Тесты выполняются против локального MSW API. Реальные брокерские счета, биржа, LLM, MCP и платежи не подключены.

## Команды

- `npm run lint` — ESLint, React Hooks и запрет импорта вверх по слоям FSD.
- `npm run typecheck` — TypeScript.
- `npm test` — Vitest, Testing Library и MSW.
- `npm run test:e2e` — Playwright Chromium, автоматически запускает Vite.
- `npm run build-storybook` — сборка каталога состояний UI.
- `npm run format` — Prettier.

Pre-commit выполняет lint и typecheck. Он не запускает браузерные тесты и не меняет файлы автоматически.

## Приоритет проверок

Проверяются ограничения и разрешения агента, точный расчет денег и комиссии, отсутствие исполнения до явного подтверждения, повторное подтверждение одной заявки, взнос сквада до и после согласования, полный выход с сохранением расчета, заработанные награды и приватность. Проверки Query подтверждают получение и обновление серверного состояния через HTTP, а не подменяют Query внутренним состоянием компонента.

Браузерные проверки используют доступные пользователю элементы, маршруты и локальное сохранение. Адаптивность проверяется на 320, 390, 768 и 1440 пикселях; фиксированные области проверяются по координатам до и после прокрутки.

## Проверенный результат

На 10 ноября 2026 года: 59 тестов Vitest в 11 файлах и 6 сценариев Playwright Chromium проходят. Проверено 28 сочетаний маршрута и ширины экрана (320/390/768/1440 px): горизонтальных переполнений и смещения навигации при прокрутке не обнаружено. Каталог 20 наград сверен с HTML; регрессии проверяют типы наград и миграцию без изменения денег, долей и полученных предметов.

Каталог Storybook содержит 8 состояний общих компонентов: основное действие, недоступное действие, ожидающий взнос, пустой журнал, ошибка запроса, загрузка, вкладки и подтверждение. Это каталог UI, а не замена проверке бизнес-сценариев.

Процент покрытия не заявляется: приоритет отдан денежным инвариантам, границам разрешений и HTTP/Query-интеграции. Playwright выполняется в Chromium; реальные устройства iOS/Android, сетевые сбои банковской инфраструктуры и настоящие биржевые операции не проверялись. MSW и сценарные ответы не являются production backend или LLM.

Дополнительный focused-аудит проверил viewer последних восьми действий, сохранённое наблюдение с Pause/Resume и обсуждением, таблицу тарифов, read-only архив с распределением и подтверждаемый сброс только данных приложения. Unit-регрессии покрывают неизменность снимка сравнения и сохранение посторонних ключей localStorage при сбросе.

В заключительном переносе UI исходный мобильный HTML используется как эталон: 16 корневых состояний и 43 вложенных состояния перечислены в аудите. Наличие обработчика не считается доказательством визуального совпадения: для вложенных окон проверяются фактическое открытие, структура, текст и размеры. Различающиеся сохранённые суммы, история и вычисляемые значения не подменяются статическими цифрами ради снимка.
